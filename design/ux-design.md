# 定员八席 (Eight Standing Seats) —— UX 设计

> **顶栏文案**：**「其静也专，其动也直」**（《周易·系辞上》「夫乾，其静也专，其动也直，是以大生焉」）。
> 它写的正是这块板的**两种状态**：闲着时蓄势专一（待命/休息/待过目）、跑起来时直取目标（运功）。
> 用字全为正面（专、直），不会被读成「板子不动了」。
>
> **三条硬约束（用户逐次给出，别再退回）**：
> ① **严格对仗**；② **句中不带「八」**（8 这个数字只由右侧计数圆标承担）；
> ③ **顶栏直出、不配悬停** —— 所以这句必须自己站得住，不能靠解释救。
>
> **沿革（三步，别再重走）**：
> ①「八席」——用户原话「看着莫名其妙」：只说了数量、没说关系。
> ②「八仙列坐」+ 五行悬停说明 —— 讲清了，但被判「写得太具体、太解释设计了」。
> ③ 现在的对句。中间还筛选过十余条（八音克谐、八极可围于寸眸、八阵、八景、八政、寂然不动感而遂通、
> 万物并作吾以观复、目送归鸿手挥五弦、星汉灿烂若出其里…），全部保留在 `design/slogan-sheet.py`
> 的数据表里，可随时重渲比较。
>
> **教训**：匾额不该解释设计。它只需是一句挂得住的话；把「为什么是八个」交给计数圆标与席位本身。
>
> 其余文案：空席「**此位虚席 · 点此就位**」；有席等你「**N 位待你**」；
> 设置行「侧边栏 · **仙班** / 默认」。量词统一用「位」。

> DSH Web GUI 的「8 个常驻 Bot 席位」原型设计。
> 状态：设计已实现并跑通。**主栏是原装对话**（只加了席位徽章），侧栏是八席网格。
> 八仙 sprite 通过盲辨识验收（6/8 剪影可辨，2/8 靠主色兜底）。

## 0. 设计支点

**槽位身份是常驻的，会话是可抛弃的负载。**

之前的失败版本把「第 n 格 = 第 n 个会话」硬绑，格子没有身份：会话增删或排序一变，格子就换人，
于是每张卡都看不出任何有意义的东西。本设计反过来 —— 8 个槽位的身份（人设、颜色、编号）永久固定，
真实会话只是挂在槽位上的可替换负载。

**Bot = 常驻身份 + 可替换会话。** `/clear` 丢掉的是会话，不是 bot。

## 1. 三个正交状态（必须分开，不能塞进一个字段）

| 维度 | 取值 | 变化频率 | 谁改 |
|---|---|---|---|
| **人设 persona** | 姓名 / 道具 / 主色 / 语气 | 几乎不变 | 用户 |
| **活动 activity** | 运功 / 休息 / 待答 / 待裁 | 高频 | agent |
| **上下文 context** | 空 / 使用中 / 接近上限 | 中频 | 系统 |

关键推论：**「休息」≠「虚席」**。休息是"有身份、已就绪、没在干活"；虚席是"这个位置还没启用"。
（界面用词统一为**虚席** —— 状态标签「虚席」、格内文案「此位虚席 · 点此就位」，同一个词。）
一个 bot 可以「休息但上下文 87% 满」—— 卡片必须提示，因为下次派活前得先清。

### 状态标签（界面上一共 7 种）

| 标签 | 什么事实 | 判定来源 | 小人 |
|---|---|---|---|
| **虚席** | 这一席还没绑会话 | 无绑定 | 收起（灰掉） |
| **待命** | 已就位，会话还是空的、没开工 | `summary.blank` | 收起 |
| **运功** | 正在干活 | `summary.running` | 本位编排 |
| **待过目** | 有一轮结束了、**你还没看过它** | `completed` 未读提醒 | 归位 + 金光余晖 |
| **休息** | 闲置，没有未读结果 | 其余 | 收起 |
| **待答** | 它抛了问题卡住，要你回话 | 投影 `attention=question` | 举旗 |
| **待裁** | 有未审的审批卡住，要你定夺 | 投影 `attention=approval` | 举旗 |

优先级：`待答/待裁` 盖过一切（除虚席）；其余按 运功 → 待过目 → 待命 → 休息。

**为什么叫「待过目」而不是「已完成」**：`completed` 不是生命周期，是**未读提醒** ——
平台在 `running` 的 true→false 边沿点亮（`client.js syncCompletedNotifications`），
**不判成败**（失败/中断同样点亮），选中该会话即清除。叫「已完成」不只是不够准，
而是**可能说错**：一轮跑挂了它照样显示「已完成」。它真正只说了两件事：
① 有一轮结束了；② 你还没看过。所以名字不许声称成功。
另：你正看着的那一席跑完**不会**点亮提醒（`s.sessionId !== this.selected` 才加），
所以「待过目」必然出现在你没在看的席位上 —— 这恰好是八席看板替你盯着的价值。

**状态点配色**：运功用绿，**待过目用金** `#C9A227`（与小人法宝上那点金光同源），
待答/待裁 用朱砂 `#B5453C`，虚席/待命/休息用灰。绿点已经被「运功」占用 ——
同一个绿不能既表示「正在干活」又表示「跑完了、待你过目」。

**语域纪律（register）**：状态标签一律古风，且「等你」类**共用「待」字一族**
（待命 / 待过目 / 待答 / 待裁，顶栏计数「N 位待你」同族）；值班类用仙班语境（运功 / 休息）。
悬停解释**保持白话** —— 解释的职责就是把古风词说清楚，不该跟着古风。
这条是用户点出来的：「工作中跟其他的语言不太对账。其他的都是古风的。」
当时的全量对账结果：跑偏的是 `工作中` / `等你回答` / `等你批准` 三处标签，
外加兜底行里**第二个现代词 `运行中`**（与「工作中」重复）和提示行的 `点开即清`；现已全部对齐。
实现落在客户端 `stateOf()` + `STATE_HINT` + `actionLine()` 三处，改文案时三处要一起改。

每个状态的**悬停解释**在客户端 `STATE_HINT` 里逐条写死（含「待过目」那句
「点开即清；不保证成功」），免得两个近义标签之间又要靠猜。

### 状态机

```
              ┌──────── 休息 ◀──────── 任务完成 ────────┐
              │           │                              │
          派活│        清空│(/clear)                     │
              ▼           ▼                              │
           运功 ──需要确认──▶ 待答/待裁 ──你回话──▶ 运功 ──┘
              │
              └──出错──▶ 异常(等你处理) ──重试/清空──▶ 休息
```

- **待答/待裁是一等状态**，不是「运功」的子状态 —— 它是唯一需要用户行动的状态，要抢注意力。
- 「异常」与「阻塞」分开：阻塞 = 它在问你；异常 = 它挂了。
- 状态迁移要有历史痕迹：刚完成的卡短暂保留 `✓ 3s` 再回静默，否则切走一次回来就不知道发生了什么。

## 2. 侧栏卡片 —— 状态驱动的三段视觉密度

硬约束：侧栏宽度 **264–420px**（`dsh-client-ui-layout/columns.ts` 的 `SIDEBAR_MIN/MAX`）。
2 列时每卡约 **120–190px**。在这个尺寸下，人眼只能做一件事：**扫出"哪张不一样"**。

所以卡片不做等量信息平铺，而是按状态切换密度：

| 密度 | 触发 | 显示 |
|---|---|---|
| **静默** | 休息 | 像素头像 + 姓名 + 灰点。**就这些，留白** |
| **工作** | 运功 | 上面 + 一行当前动作（`Grep actionType` / `Edit StyleItemMapper.kt`） |
| **召你** | 阻塞 / 异常 | 整卡边框亮起（**朱砂，不用品牌色**） + 一行**为什么**需要你 + 头像停转并显示提示符 |

> 8 张卡都在动 = 8 张卡都没在说话。

条件显示（不常驻）：
- 上下文占用 —— 仅 >75% 时以细进度条出现
- 完成未读 —— bot 干完但你没点开，一个绿点（可直接复用 DSH `SessionSummary.completed`）
- 工作目录 —— 侧栏 ≥340px 显示 basename + 分支；264px 时藏进 tooltip（主栏有完整版）

**不显示在卡片**：token 数、成本、会话内容 —— 只在主栏。

### 布局选择

推荐 **2×4 等大网格**。理由：核心诉求是"并排扫视"，2×4 一屏放完不需要滚动。
并在 264px 宽度下就按最简态设计（头像+名+状态点），把"工作摘要行"当作 ≥320px 的增强 ——
这样最窄情况不掉链子。

## 3. 主栏 —— **保留原装对话，只做定位升级**

> **不造轮子。** 主栏就是 DSH 原装的 Conversation：原装的消息渲染、原装的工具视图、
> 原装的 composer、原装的 Chat/Trajectory 标签、原装的底部统计。
> 本设计**不重写**其中任何一块。

席位切换靠**换会话**，不靠换面板：

```
点侧栏席位  →  sessions.open(该席绑定的 sessionId)  →  主栏原装对话显示那一席的会话
```

于是主栏与侧栏是**同一份状态的两个分辨率**：侧栏是 8 席的粗粒度总览，
主栏是选中那一席的完整原装视图。

### 唯一的升级点：对话头的席位徽章

原装对话头的标题旁有一排「Session actions」座位（`conversation.session.header.actions`）。
在那里注入一个席位徽章：

```
项目上下文与进展梳理 / Red-team the static junction…  ⇅  ◇ Standard mode  [仙姑·文档/整理]
                                                                          ↑ 席位徽章
```

- 24px 像素头像（**整数倍**，1:1 才清晰）+ 姓名 + 职能，整块用该席主色着色
- 只读绑定表反查：**不属于任何席位的会话不渲染徽章**，原装对话头保持原样
- 不改原装布局、不接管任何控件，只在标题簇里加一个内联块

这一层是「基于新定位」的全部：让「我正在跟哪一席说话」在原装 UI 里可见。

### 早期方案的错误（记录在案）

第一版把主栏做成自制详情页：96px 头像 + 自制动作条 + 自制「绑定会话」表 +
一个占位的「完整信息区」。结果**把原装对话整个扔了**，点开席位看不到对话 ——
这是典型的造轮子。已全部删除，主栏回归原装。

### 卡片上的「内容与过程」—— 需要 host 侧投影

需求是「侧栏卡片像 8 个 cmux 窗口，直接看到一部分内容和过程」。
**纯客户端做不到**，实测（探针跑在真实 GUI 上）：

| 席位 | binding | 事件窗口 entries |
|---|---|---|
| 钟离 / 洞宾 / 铁拐 / 张果 | ✓ | **0** |
| 仙姑（当前上台） | ✓ | **265** |
| 采和 / 湘子 / 国舅 | ✓ | **0** |

原因写在 `dsh-api-session-controller` 的 `followCurrent()` 文档里：

> **"Staging IS the open signal — the window opens ⟺ the session is on stage"**

事件窗口只为「当前上台」的那个会话打开，其余会话的 binding 存在但窗口是空的。

**正解是 session-projection 这条官方扩展缝**（host 侧）：

```
host   : ctx.sessionProjections.register({ key:'seat-activity', init, apply, wire, stateVersion })
           ↑ 框架在每条已提交的会话事件上主动驱动这个纯 fold，不需要自己订阅
client : summary.projectionValues['seat-activity']
           ↑ 客户端 buildListSnapshot() 把 projectionStore.values() 摊进 summary
```

`title` 已经在走同一条路径，所以这不是偏方。

**已实现**（`lib/index.js`）：fold 只保留展示所需的短字符串 —— 最后一条 `tool/call` 的
`{工具名, 参数摘要}` + 最后一段 `assistant/message` 的文本。参数摘要按已知键优先取用、
路径取 basename、截断 52 字符；非法 JSON 安全降级。state 是纯 JSON（可持久化），
且对不关心的事件**返回同一引用**（`Object.is` 零下游工作，这是该 API 的性能前提）。

**遗留限制（实测）**：fold 需要会话日志**在内存里**（`snapshot()` 文档：
"fold lazily over the **in-memory** log"）。所以一张卡片要显示过程，
该会话必须在本服务器进程里被打开过至少一次：

- 打开一次 → 该席立刻显示真实工具调用（**已验证**）
- **冷启动 / 服务器重启后 → 8 席都退回通用状态，需要重新预热**
- 写 localStorage 不解决（投影值不走 localStorage）

要彻底修掉冷启动，需要 host 侧在启动时**主动遍历 8 席会话、加载日志并 materialize 投影**
（`ctx.sessionQuery.listSessions()` + `snapshot(session, ['seat-activity'])`），
并确认这样会产生推给客户端的 change frame。这是一块还没做的工作。

### 逃生开关：设置里的「侧边栏」模式

用户要能**随时切回原生侧边栏**，而不是去改 patch 文件 + 重启。
落点是 `settings.general.item` —— 官方描述正是「one setting that needs no page of its own」，
契约注明 **owner 不传任何 props、也不投影 label，整行自己画**。

```
设置 → 通用
  侧边栏                                    [ 仙班 │ 默认 ]
  仙班 = 定员席位网格（其静也专，其动也直）；默认 = 原生会话浏览
```

**实现的关键不是隐藏组件，而是卸载注册。** 八席网格以 `priority: -1` 遮蔽内置
WorkspaceBrowser（priority 0），single slot 的渲染取 priority 升序的 index 0 ——
所以只要 `dispose()` 掉我们的注册，内置浏览器**自动回到渲染位**：

```js
registerGrid = () => ctx.slots.register({ name: "sidebar.workspaces", priority: -1 }, SeatGrid);
// 关：dispose()  -> 内置 WorkspaceBrowser 回来（已验证：New Session | Workspaces | …）
// 开：再 register -> 网格回来
```

**持久化**走 host 侧设置命名空间（`agent-grid.sidebar = 'grid' | 'default'`，
host 有 zod/schemastery schema + settings-file 持久化；客户端只读/写）。

**优雅降级**：开关先本地生效、再尽力持久化。如果部署里没有 settings 服务
（或 host 半边还没重启加载），开关**仍然可用**，只是行内提示会变成
「当前无法持久化，重启后复原」。实测过这条路径。

持久化验证过的三种情况：
- 页面刷新后保持 ✓
- **服务器重启后保持** ✓（实测 `gridPresent: false` + 原生 Workspaces 列表）
- host 半边缺失时降级为本地开关 ✓

**范围**：这个开关只管侧边栏。对话头里的**席位徽章不受它控制** ——
切回默认侧边栏后徽章仍在（实测确认）。要不要一起管，等用户决定。

### 8c. 两个「会话找不到」的 bug（实测，都已修）

用户反馈：*「切过去之后点开全是 subagent，就连这条对话都找不到」*。复盘出**两个独立的问题**。

**① 播种没过滤子会话 → 8 席里 6 席绑到了 subagent**

`SessionListState.ids` 里**含子会话**（`SessionSummary.origin === 'subagent'`）。播种时直接
`ids.slice(0, 8)` 就把 6 个 `delegationDepth=1` 的子会话塞进了席位。症状：点开席位看到的是
子 agent 的 transcript（正文里写着 "Result sent to the parent agent"），自己的会话一个都看不到。

实测数据：

| 席位 | 旧绑定 depth | 新绑定 depth |
|---|---|---|
| 钟离 / 洞宾 | 0 | 0 |
| 铁拐 / 张果 / 仙姑 / 采和 / 湘子 / 国舅 | **1（子会话）** | **0** |

修：`isSeatEligible(s) = !!s && s.origin !== 'subagent' && s.parentId === undefined`，
播种与自愈都用它。存储升到 **v3**，v1/v2 一律不读、直接重新播种（那份数据没有修复价值）。

**② 网格把会话浏览区整个换掉了 → 没入席的会话没有入口**

这是更严重的设计缺陷：`sidebar.workspaces` 是 single slot，网格一挂，内置
WorkspaceBrowser 就整个不见了。所以**任何没绑到席位的会话都变成不可达** ——
包括当前正在进行的对话。

修：网格底部补两样东西：
- **「未入席」列表**（最多 4 条最近的非子会话、且未被任何席位占用）
- **「浏览全部会话 →」** 按钮，一键切回默认侧边栏

**③ 顺带修的语义混淆**：`blank`（空白会话）原本被归成 `empty` 画成灰色，
但「绑了一个空白会话」是**已就绪待命**，不是「未启用」。现在 `empty` 只留给真的没绑会话的席位
（实测之前有 3 个席位被误画成灰的）。

修完的端到端验证：点 1 号席 → 主栏标题从「项目上下文与进展梳理」变成
**「DSH UI 自定义程度」**（就是当前这条对话），徽章显示 `钟离 · 总控/规划`，卡片高亮。

## 4. `/clear` 的精确语义

> `/clear` = 结束当前任务 + 把这一席的**模型上下文整个清空**（并重置 goal / plan mode），
> **保留人设、工作目录、槽位编号、标题** —— 效果等价于「在同一席新开一个对话」。

清掉的是**模型看得见的全部**：
- surface 全清，**连首个 system prompt 一起** —— 下一个 turn 重新渲染的是当前那份
  （AGENTS.md / 工具表 / skill 目录 / runtime context 都取最新，不是会话开始时的旧快照）；
- goal 清掉、plan mode 关掉；todos 不用管（`todo/write` 投影在 `turn/start` 自己重置）；
- 不留 `[clear]` 这类模型可见的标记。

不动的是：人类聊天记录（transcript 读 append-origin 事件，replacement 只对模型生效）、
人设、工作目录、槽位、标题。

理由：bot 身份常驻，任务才可抛弃。清完 bot 回到「休息」，头像回到呼吸动画，槽位不变 —— 下次找它还在原位。
但「清空上下文」必须是真清：留着旧 system prompt 不叫新对话，那只是把历史剪掉一半。

边界情况：
- 正在工作时执行 → 先中断，再**二次确认**（"王翦 正在跑，清空会丢弃本轮。确认？"）
- 清空后卡片短暂显示 `已清空 · $0.31 / 142k`，让用户知道丢了什么（否则会怀疑没生效）
- 不做"清空全部 8 席"的批量命令，除非二次确认 —— 8 席上下文同时丢失代价太大

## 5. 像素头像规范

### 规格

- 逻辑画布 **56×24**：**只加宽、不加高**。横向 56 格（2× = 112px）把 116px 的卡片内宽吃满，
  身体仍是 24×24 放在 (16, 0)；纵向等于身体高度，不留余量 ——
  卡片高度是稀缺资源，起伏做成 **1–2 格（2–4 CSS px）的小幅**就够，
  不值得为「飘 3 格」把整块板垫高（用户：「你是不是在改 icon 本身的高度？不要加大高度，
  动作不能起伏高低一点吗」）。上一版曾把画布加到 28 高去容纳大跳，被叫停并回退。
  画布宽度的演变：24（左右各空 30px，法宝没处使劲）→ 48（2× 96px，只用内宽 86%）→ **56**（吃满）。
- **必须整数倍放大**：上一版渲染在 32px = 1.33×，每个像素落成 1px/2px 不均的宽度，
  像素一糊，八席之间好不容易拉开的剪影差别也跟着糊。2× 下每像素恰好 2×2 设备像素。
  动效位移也一律取**整数精灵像素**（2× 下 1 单位 = 2 CSS px）——半像素位移会让整只小人糊掉。
- 调色板全局锁定：1 描边 + 2 肤色 + 1 白 + 1 墨 + 木/金属/纸 + 每席 3 阶主色
  —— **限制调色板是"精致感"的真正来源，不是细节量**（新增 `B` 朱砂 / `C` 朱砂暗，只给旗用）
- 48px 下人脸是糊的 → 靠**道具剪影 + 冠型**区分身份，不靠脸
- **分层**（每席 10 个 symbol）：`body` 头身冠须（四态共用）· `p-<态>` 法宝位姿 ·
  `x-<态>` 贴着法宝外缘长出来的广域动效 · `f-ask` 朱砂旗面（单独一层，因为只有它要单独摆）。
  四态 × 八席 = 32 种姿势，但矩形数只比原来的 2 态多一成 —— 身体只画一份，动作交给 CSS。
- 合成表按**行游程压成 `<path>`**（`M x y h n v1 h-n z`）：一个 symbol 一种颜色一条 path。
  实测 **38KB / 80 symbol**；若仍按「一像素一个 `<rect>`」写，四倍姿势会把 client.js 从 290KB
  推到 1MB 级。反而比旧的两态版小了 3.7 倍（79KB vs 290KB）。

### 动画 = 有限状态机（不是循环 GIF）

四态，姿势跟着**事实**走（不是跟着装饰走）；动作全部由 CSS transform 驱动，
所以 sprite 只需出姿势、不必出中间帧：

| 态 | 触发事实 | 法宝 | 动作 | 节奏 |
|---|---|---|---|---|
| `rest` 休息 | 其余 | **收起**（下沉 2 格、靠身、压暗到 saturate .55） | **完全静止**：三层 `animation:none`，实测 2.6s 零位移 | 无 |
| `work` 干活 | `summary.running` | 在本位，动效画在法宝自己身上 | **按法宝分语法，八席八套**（见下表） | 每席不同 |
| `ask` 等你 | 未答复的 `approval/asked`、`ask_user_question` | **举起**（上抬 2 格、微外展） | **身体不动**，只举宝 1 格 + **左侧朱砂旗摆动**（旗杆固定 x=4，旗面单独一层） | 1.6s / 0.9s |
| `done` 归位 | `summary.completed` | 归位（下沉 1 格） | 只有明暗：法宝余晖 opacity 呼吸，**位置不动** | 2.4s |

**三条纪律，每条都是被实测（和用户反馈）逼出来的：**

一、**静止就是静止**。八席里常态有五六席闲着，若每席都做位移，等于整块板一直在抖：
注意力被「没在干活的人」占掉，还白烧六份动画。休息态三层 `animation:none`，
实测 2.6s 零位移。闲着的状态交给色点、压暗的法宝、「多久没动」那行字去说。
用户原话：「空闲和休息的就不要跳了吧？」

二、**身体必须动，而且八席八套**。中间踩过两个坑：
初版所有人共用一套「左右踱步」——八个角色同一个动作，法宝的身份感全丢
（用户原话：「每个人都一样，只是衣服不一样的一样的机器人」）；
改完又只剩法宝 1 个精灵像素的微动（= 2 CSS px），肉眼就是静止
（用户原话：「工作中的怎么也不动了？」）。所以现在每个席位一条**完整编排**，
四条通道全部按人不同 —— 这才是「一看就看到多样性」的全部来源：

| 通道 | 含义 | 八席取值 |
|---|---|---|
| `offset` 基准站位 | 不在场中央，各人站各人的地方（**全状态生效**） | −8 / +3 / +7 / −4 / −2 / +5 / −6 / +2 格（跨度 15 格 = 30 CSS px） |
| `body` 身体步态 | 单向步进，不是对称摆动；**纵向幅度 0–2 格**（小幅起伏） | 踱方步（三步一跨回）· 出剑前刺（突进两拍）· 瘸步巡行（单向挪）· 倒骑慢摇（大摆一停）· 凌空飘浮（斜向）· 蹦跳采花（逐跳向右）· 倚箫轻摇（倚住两拍）· 端立击板（一拍跺地） |
| `prop` 法宝动作 | 作用在「法宝 + 出效 + 旗」这一组上，所以出效随法宝一起走 | 挥扇 / 抽剑 / 沉葫芦 / 摇鼓 / 开合荷 / 提篮 / 举箫 / 合击板 |
| `fx` 出效漂移 | 叠在组的变换之上 | 风纹 / 寒光 / 药气 / 声波 / 花瓣 / 冒花 / 音符 / 纯明暗 |
| 周期 | 节奏也要不同 | 0.9 / 1.4 / 1.5 / 2.2 / 2.6 / 3.6 / 4.0 / 4.4 s（八种） |

实测横向摆幅 5–9 格（10–18 CSS px），八席画面内容占画布 **1..48 / 56 格**（上一版只占中间 36 格）。

**「不要都对称来回」是硬约束，不是口味**：上一版八席里六席都是「左一下右一下」的对称摆动，
换汤不换药。现在**7/8 是单向步进**（走三步再跨回 / 突进两拍 / 单向挪步 / 逐跳向右），
只有国舅那次跺地是对称的 —— 那正是「端立击板」该有的样子。
`baxian.py` 自检里直接拦：方向反转 ≤2 次、位移 ≥2 格、**对称席位 ≤2 个**，超了 exit 1。

行为**形状**刻意拉了三种：横向为主（钟离/铁拐/张果/湘子）、纵向为主（仙姑/采和/国舅）、
混合（洞宾）；铁拐是**不对称三拍**（瘸），湘子的关键帧里有**两个相邻同值 = 停顿**，
国舅是**只在一拍上顿一下**、出效只做明暗 —— 不是同一套模板换参数。

三、位移一律**整数精灵像素**且 `steps(1,end)` 逐格停留，绝不插值 ——
2× 下 1 单位 = 2 CSS px，一插值就出现半像素，整只小人就糊了。

四、**纵向只做小幅起伏**（1–2 格），横向才是动作的主战场（5–9 格）。
纵向大跳需要给画布加高，而加高会连带抬高每张卡片、挤压整块板 —— 不划算。

**CSS 尺寸必须与画布严格整数倍**（这条也是踩出来的）：把画布高度从 28 改回 24 时漏改了
`viewBox`，于是 CSS `112×48` 对上 `viewBox 56×28`，`preserveAspectRatio` 把精灵按
**1.714× 非整数**缩放，像素整片糊掉且**没有任何报错**，只有量缩放比才发现。
现在 `build_client.py` 直接断言三处一致：舞台 = 画布 2 倍、徽章 = 1 倍、`viewBox` = 画布尺寸
（实测改错会 exit 1）。

**编排数据在 `design/baxian.py` 的 `CHOREO`**（和 sprite、角色、主色同源），
由 `build_client.py` 经 `/*__CHOREO__*/` 标记注入客户端 CSS；加第九席只改一处。
构建期断言（`build_client.py` + `baxian.py` 自检，都实测过会拦）：
每个席位必须有编排；**动作不许把画面内容推出画布**（容差 ±3 格 —— 舞台外还有卡片 6px 内边距，
「剑气破格」落在内边距里是有劲，顶到上一张卡才是错）；**不许对称来回**（见上）。

**广域动效的锚点纪律**：动效一律取法宝**包围盒的外缘**为起点，方向取留白更多的一侧。
第一版把动效写死在 `x=36..43`，八件法宝里有一半离得远，到 card 尺寸下就成了「天上几点灰」；
胸前法宝（箫/玉板）更要特殊处理 —— 它们的包围盒落在躯干里，直接以它为界会把动效**画在袍子上**，
必须以**躯干剪影**为界往外画。

**「等你」的旗必须每次出现在同一个位置**：第一版按包围盒算左右，结果铁拐（杖在左）的旗杆跑到画布最右、
旗面还留在最左 —— 旗成了两半。信号类元素的位置稳定性优先于构图自由度。

**旗后来并进了「法宝+出效」那一组**：站位偏移到 −8…+7 格之后，钉死在画面里的旗会出现
「人站左边、旗还在中央」的错位。旗是「他举的旗」，就该跟着人走；同理出效也跟着法宝走。

**注意力与性能纪律（必须有）**：只有**选中**或**状态刚变化**的卡片全速播放；
其余降速到 1 帧/2s 或静止。8 个动画同速跑 = 视觉噪音 + 持续占 CPU。
同时尊重 `prefers-reduced-motion`：降级为静态帧 + 状态点颜色。

## 6. 盲辨识验收结论（实测，非假设）

在 48px、深色底、遮住名字的条件下：

| 结果 | 席位 | 依据 |
|---|---|---|
| ✅ 一眼可辨 | 仙姑 | 唯一粉色 + 头顶荷花 + 垂发 |
| ✅ 一眼可辨 | 国舅 | 展脚幞头的两侧长横翅 |
| ✅ 一眼可辨 | 洞宾 | 头顶长出画面的竖剑 |
| ✅ 一眼可辨 | 铁拐 | 唯一在左侧的竖杖 + 玄灰 |
| ✅ 一眼可辨 | 湘子 | 胸前斜线（唯一斜置道具） |
| ✅ 一眼可辨 | 钟离 | 赭红 + 右侧大片绿叶 |
| ⚠️ 靠颜色分 | 张果 / 采和 | 剪影都是「右侧一个木色容器」，但松绿 vs 靛蓝分离得开 |

**结论**：`剪影足以区分身份` 这个假设**只对 6/8 成立**；剩下 2 席靠主色兜底。

因此设计的正确分工是：

- **头像负责「性格 + 状态」**（谁的风格、在不在忙、是不是在等你）
- **姓名 + 主色负责「身份」**（这是谁）

这直接推出一条硬性 UI 约束：**卡片必须始终显示姓名**，姓名不可省略、不可 hover 才出。
上一套的教训是：只靠剪影做身份识别是不可能的，别再把设计压在这一点上。


### v1 的失败教训（记录在案，避免回退）

v1 在 48px 下完全认不出人，三个原因：
1. **没有手臂** —— 袍子是一个梯形块，读起来像棋盘兵不是人。
   v2 用「亮臂 / 暗缝 / 中调躯干 / 暗缝 / 亮臂」的明暗节奏把手臂读出来。
2. **帽冠整块填了描边色** → 渲染成一条黑杠。v2 冠只描边、内部填色，
   并定了一条铁律：**任何一行都不允许是整行纯描边**。
3. **道具只有 1px 宽** —— 48px 下不可见。
   v2 原则：**道具必须突破身体剪影**（伸到肩上/身侧/身前/身下），否则看不出身份。

## 7. 与 cmux 参考的继承 / 偏离

**继承**：人设命名、忙/空闲语义、`Esc` 中断、`Esc Esc` 清空、工作目录+分支常显、每席独立输入。

**必须偏离**：cmux 是 8 个窗口**都显示完整对话**；本设计是「侧栏轻量 + 主栏单一详情」。
侧栏只有 264–420px，物理上放不下 8 份对话 —— 这是约束逼出来的，不是取舍偏好。

## 8. 落地约束（已实测）

| 位置 | slot | 关键约束 |
|---|---|---|
| 侧栏 8 格 | `sidebar.workspaces` | single/root。**必须传 `priority: -1`**，否则与内置 WorkspaceBrowser 撞 priority 0 直接抛错。遮蔽内置 UI 是显式 opt-in |
| 侧边栏开关 | `settings.general.item`（list/root）+ `settingsScope` | owner 不传 props；关 = dispose 掉 priority:-1 的注册，内置浏览器自动回来 |
| 席位徽章 | `conversation.session.header.actions` | list/session，owner props 为空；只收标准 session props（`sessionId`）|
| 卡片内容/过程 | `sessionProjections`（**host 侧**）| fold 需要日志在内存 -> 见上一节「遗留限制」 |
| 席位切换 | `sessions` 服务 | `sessions.open(id)` 换 current。**用 `ctx.inject(['sessions'], cb)` 回调取服务**，apply 顶层 `ctx.get()` 可能拿到 undefined |
| 卡片数据 | `useSessions` | `running` / `completed` / `blank` / `updatedAt` / `jobsBySession` 可用 |

其他已实测约束：
- 客户端半边是**纯 JavaScript，无 JSX、无 TypeScript**，一律 `React.createElement`
- `inject` 用的是**服务名**（`slots` / `layout`），不是包名；包名写在 package.json 的 `dsh.client.inject`
- 客户端代码**真 HMR**（改文件不刷新页面即生效，已用全局标记验证）；
  但重挂瞬间 8 个 `main` 注册消失，`retainMainPanels` 会把选中面板清回对话态
- 像素头像在非整数倍尺寸下**必然糊**。24 网格只能用 24 / 48 / 96；
  折叠轨道里我一开始写了 20px（0.83 倍），改成 24px 才清晰

### 8b. 实现中踩到的三个 bug（都会静默失败，值得记）

**1. 绑定表在首次渲染时被清光（数据丢失级）**

`reconcile()` 拿 `SessionListState.ids` 判断"绑定的会话是否还活着"。
但首次渲染时会话列表的 `phase` 还是 `'pending'`，`ids` 是**空数组** ——
于是全部绑定被判定为"会话已死"并删除，刷新一次页面 8 席全变空槽。

修：只在 `phase === 'ready'` 时裁剪。`SessionListPhase = 'pending' | 'ready'`，
`ready` 才代表列表是权威的。

**2. 「清空重做」当场自我撤销**

删掉绑定后，下一次渲染里"首次分派"逻辑发现该席没有绑定，立刻又给它抓了一个会话补上。
用户点清空，看起来什么都没发生。

修：存储里加 `seeded` 标志。分派只发生一次；之后「没有绑定」就是「用户清空了」。
`readStore()` 还要兼容旧格式，否则老用户的绑定会被丢弃。

**3. sprite id 打错 → 格子渲染成空白，且不报错**

插件里的席位 id 我从上一版抄成了 `kongming`（诸葛亮的 id），
而生成器产出的八仙 id 是 `hanzhongli`。`<use href="#kongming-body">` 指向不存在的 symbol，
React 和浏览器都不报错，格子就是空的。**只有盯着截图才能发现。**

修：`build_client.py` 加构建期断言 —— 模板引用的每个 id 必须存在于 sprite 表。
**分层之后这条断言升级为逐层校验**：每席必须齐备 `body` + `p-<态>` × 4 + `x-<态>` × 4 + `f-ask`
（缺任何一层同样是静默空白）。已验证：把 id 改成 `kongming` 会 exit 1 并列出全部 10 个缺失层。
运行期另有一道——`use.getBBox()` 面积为 0 即判定静默空白，`work` 态的动效层必须有内容。

教训：这类"引用了一个不存在的东西"的失败在 UI 里是静默的。
凡是字符串 key 跨两个文件（Python 生成器 ↔ JS 消费方）传递，就必须有构建期校验。
